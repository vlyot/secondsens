## Project Overview

React + TypeScript + Vite frontend backed by a Go (Gin) REST API, using Tailwind CSS v4, shadcn/ui, Google Gemini for LLM calls, and Supabase for auth + history persistence.

**Key Technologies**:
- React 19.2.0 with TypeScript
- Vite 7.x for build tooling
- Tailwind CSS v4 (via `@tailwindcss/vite` plugin)
- shadcn/ui components ("new-york" style) with Lucide icons
- Go 1.24 + Gin for the backend API
- Google Gemini (`gemini-2.5-flash`) for LLM calls
- Supabase for auth (frontend OTP magic link) + history storage (backend service role)
- Swagger (swaggo/swag) — auto-served at `/swagger/index.html`

**Critical Rules**:
1. Always use typography components instead of raw HTML + Tailwind
2. Check shadcn/ui (`@/llms.txt`) before creating custom components
3. Use Lucide icons — **NEVER use emojis in the UI**
4. Maintain semantic HTML for accessibility

## Development Commands

Run from the **repo root** (`secondsens/`):

```bash
npm start           # Start both backend + frontend concurrently (recommended)
npm run dev         # Frontend only (Vite HMR)
npm run dev:backend # Backend only (go run src/main.go)
npm run build       # TypeScript check → Vite production build
npm run lint        # ESLint
npm run test:run    # Vitest single run
```

Backend (run from `backend/`):

```bash
go test ./...                                # All packages
go test -run TestName ./src/package          # Single test
go vet ./...                                 # Static analysis
go build ./...                               # Compile check
# Regenerate Swagger after changing handler annotations:
go run github.com/swaggo/swag/cmd/swag@latest init -g src/main.go -o docs
```

## Architecture

### High-Level Data Flow

```
Browser (React SPA)
  └─ frontend/services/api.ts  (fetch)
       └─ Go Gin server :8080
            ├─ /api/products     → products package (YAML catalog + LLM validation)
            ├─ /api/recommend    → prices + recommendations packages (Gemini)
            ├─ /api/history      → history package (Supabase, JWT-gated)
            └─ /swagger/*        → swaggo auto-generated UI
```

### Frontend Navigation (State Machine)

Navigation is **not** React Router — it is a state machine in `frontend/App.tsx`.

```
AppStep = 'landing' | 'search' | 'sliders' | 'results' | 'disambiguation'
        | 'compare_disambiguation' | 'error' | 'docs' | 'auth' | 'history' | 'profile'
```

- `landing`, `search`, `docs` render full-page outside the card layout
- All other steps render inside `BackgroundLayout → Card`
- `FlowBreadcrumbs` renders step progress + auth nav (History / Profile / Sign in icons)
- After a successful recommendation, history is saved fire-and-forget if user is signed in
- **Compare mode**: `AppState` carries `isCompareMode`, `compareQuery`, `compareProduct`, `compareRecommendation`, `compareDisambiguation`. The `compare_disambiguation` step handles ambiguous compare products independently of the primary flow.

### Auth Flow

- **Frontend**: `frontend/context/AuthContext.tsx` wraps the app in `<AuthProvider>`. Uses Supabase email OTP. `session.access_token` is passed as `Authorization: Bearer` on all `/api/history` calls.
- **Backend**: `shared/auth_middleware.go` validates the JWT with `SUPABASE_JWT_SECRET`, sets `user_id` in Gin context. History routes only activate when all three Supabase env vars are present.

### Backend Packages

| Package | Responsibility |
|---------|----------------|
| `main` | Gin setup, route wiring, Swagger, CORS |
| `shared` | Config, in-memory cache, Gemini client, Supabase REST client, JWT middleware, domain types |
| `products` | YAML catalog, fuzzy search, LLM dynamic product validation |
| `prices` | Gemini-powered real-time price fetch per condition tier |
| `recommendations` | Ranked Buy New / Used recommendations via Gemini; supports optional `compare_product` for parallel dual-pipeline |
| `history` | `POST /api/history` + `GET /api/history` (auth-gated, Supabase-backed) |

### In-Memory Caching

- Product validation: 10,000 entries, 7-day TTL
- Recommendations: 10,000 entries, 24-hour TTL
- Cache key: FNV32 hash of preference values concatenated with canonical product name
- In compare mode, each product checks the cache independently — cache hits cost zero extra Gemini calls

### Environment Variables

**Backend** (`backend/.env`):
| Variable | Required | Default |
|----------|----------|---------|
| `GEMINI_API_KEY` | Yes | — |
| `GEMINI_MODEL` | No | `gemini-2.5-flash` |
| `SUPABASE_URL` | For history | — |
| `SUPABASE_SERVICE_ROLE_KEY` | For history | — |
| `SUPABASE_JWT_SECRET` | For history | — |

**Frontend** (`frontend/.env`):
| Variable | Notes |
|----------|-------|
| `VITE_API_BACKEND_URL` | Defaults to `http://localhost:8080` |
| `VITE_SUPABASE_URL` | Required for auth |
| `VITE_SUPABASE_ANON_KEY` | Required for auth (safe to expose) |
